# Сердечки в кабинете владельца: подготовка к общему Favorite API

30 октября 2026. Реализована только часть Ольги, без изменения каталога,
страницы вещи, авторизации, Prisma и backend избранного.

## Готово в owner UI

- На всех OwnerItemCard есть сердечко из общего IconButton, зона нажатия 44×44.
- Активное состояние управляется item.isFavorite, без отдельного локального избранного.
- Нажатие передаёт id и целевое состояние; до подтверждения визуальное состояние не меняется.
- Повторный запрос для той же вещи блокируется, ошибка показывается через role=alert.
- Если общий adapter не подключён, кнопка отключена с подписью «Favoriten sind bald verfügbar».
  В этом случае aria-pressed не выдаёт неизвестное состояние за сохранённое false.
- Черновик нельзя добавить. Уже сохранённое скрытое объявление можно убрать,
  когда подключён adapter; это соответствует сохранению Favorite при unpublish.

## Точка подключения после готовности API Яны

OwnerItemsStore имеет необязательный метод:

```ts
setFavorite?: (id: string, isFavorite: boolean) => void | Promise<void>;
```

OwnerItem поддерживает необязательный isFavorite. После появления общего API:

1. Передавать серверный isFavorite в owner items DTO/query для текущего пользователя.
2. В useOwnerItems подключить общий Favorite hook/adapter и вернуть setFavorite.
3. Adapter вызывает согласованные PUT/DELETE /api/me/favorites/:itemId и после
   успеха обновляет/инвалидирует owner items и общий кеш Favorite/каталога.
4. При ошибке отклоняет Promise; состояние не меняется. Не добавлять owner-only
   localStorage, второй API или отдельную Prisma-модель.
5. Проверить reload, смену аккаунта и одинаковое состояние во всех карточках.

Пока шаги подключения не выполнены, production-сердечки намеренно не активны.
Они не отправляют запросы к ещё не существующему API. Глобальное постоянное
избранное не считается реализованным этим пакетом.
