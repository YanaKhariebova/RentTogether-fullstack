## Макет и результат

Ориентиры: [макет](design-reference.jpg) и [PNG каталога](design/catalog-reference.png).
Использованы контурные символы: лупа — Entdecken, сетка — Meine Anzeigen,
облачко — Anfragen, пользователь — Profil. Для существующего Favoriten добавлено
сердце в той же стилистике. Активный раздел подчёркивается, как на макете.

Один набор SVG используется в desktop Header, боковом меню и трёх основных
действиях нижней панели. Логотип и тексты ссылок сохранены; SVG декоративные
(`aria-hidden`, `focusable=false`), доступные имена задаются текстом ссылок.
На desktop 1024–1199 px подписи визуально скрыты для компактности, но остаются
доступны скринридеру; `title` даёт подсказку. От 1200 px иконки стоят рядом с текстом.
В drawer и нижней навигации подписи видны всегда. Кнопки/ссылки сохраняют зоны
нажатия от 44×44 px, нижняя панель остаётся высотой 56 px плюс safe area.

Новая библиотека иконок, зависимости и растровые картинки не добавлялись.
Логика авторизации, темы и закрытия/фокуса burger menu сохранена.

## Согласование Nachrichten и непрочитанных сообщений

Вариант навигации для будущего чата подтверждён Владом для передачи Яне:

- На mobile нижняя панель сохраняет три основных действия. `Nachrichten`
  размещается в гамбургер-меню с красным badge числа непрочитанных.
- При нуле badge скрывается; для числа больше 99 отображается `99+`.
  Доступная подпись должна сообщать число непрочитанных текстом.
- На desktop `Nachrichten` будет отдельным пунктом Header с таким же badge.
- Дополнительное предложение Влада: небольшой красный индикатор на закрытой
  кнопке гамбургера при наличии непрочитанных. Это предложение нужно согласовать
  с Яной перед реализацией; число показывается возле `Nachrichten` внутри меню.

Header и мобильную навигацию интегрирует Влад. Backend/frontend чата делает Яна.
Сейчас Яна готовит контракт и изолированные компоненты чата; Header и мобильную
навигацию она не меняет. Prisma-миграцию, API и подключение навигации начинаем
после review PR #37–39, mobile, deployment и финальной проверки MVP.

### Маршруты и API, предложенные Яной

Оба маршрута защищённые, внутри существующего `/account`:

- `/account/messages` — список диалогов, сюда ведёт пункт `Nachrichten`.
- `/account/messages/$conversationId` — конкретный диалог.

Число непрочитанных для Header:

```http
GET /api/conversations/unread-count
```

```json
{ "unreadCount": 0 }
```

При `unreadCount: 0` badge скрывается. Значения больше 99 сокращает до `99+`
сам Header; API возвращает число, а не строку для отображения. Пункт `Nachrichten`
должен оставаться активным также внутри конкретного диалога.

Способ и частота обновления счётчика, обработка загрузки/ошибки и отметка диалога
прочитанным этим сообщением не определены; их согласуем в полном контракте
перед подключением. Не добавляем polling или realtime заранее.

Этот раздел фиксирует согласование. Маршрут чата, API, badge и индикатор пока
не реализованы; неработающие ссылки в интерфейс не добавляются.
