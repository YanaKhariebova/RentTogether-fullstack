# Проверка сайта RentTogether

Проверена локальная версия с мобильными изменениями из PR #37. Исправления находятся
в отдельной ветке `fix/site-audit`, основанной на `feat/mobile-pwa`. Самостоятельного
объединения в main и deployment не выполнялось.

## Найдено и исправлено

1. Входящие заявки дополнительно фильтровались по отображаемому имени арендатора:
   имя `Du` скрывало настоящую заявку. Удалена фильтрация по имени; приватные списки
   уже разделяет сервер по авторизованному пользователю.
2. Ошибки принятия, отклонения, изменения статуса и отмены заявки не отображались
   в списках. Теперь сообщение API видно через `role=alert`. При ошибке загрузки
   списка есть кнопка повторной попытки.
3. При сбое запроса занятых дат карточка вещи показывала календарь с пустым списком
   ограничений. Теперь загрузка обозначена отдельно; после ошибки форма дат скрыта,
   показаны сообщение и повторная загрузка доступности.
4. Отклонённый `mutateAsync` при отправке заявки оставался необработанным Promise.
   Обработан отказ; форма продолжает показывать ошибку мутации и допускает повтор.
5. Сбой избранного в каталоге/карточке вещи был незаметен пользователю. Добавлено
   сообщение об ошибке, состояние сердечка при неудачном сохранении не меняется.
6. Создание заявки не инвалидировало кеш «Meine Mieten». Из-за общего staleTime
   30 секунд ранее посещённый список мог показывать старые данные. После успешного
   создания обновляется запрос аренд текущего пользователя. Регрессия проверяется
   переходами внутри SPA без `page.goto`, который очистил бы кеш.
7. `format:check` выдавал 168 ошибок на Windows из-за CRLF в checkout. В конфигурации
   Prettier задан `endOfLine: auto`: Windows CRLF и Linux LF принимаются без массовой
   перезаписи файлов команды. Полная проверка форматирования теперь проходит.

API, Prisma, миграции, авторизация и правила бронирования не менялись.
Новых зависимостей и переменных окружения нет.

UI-проверки включают публичные страницы и 404 без JS-исключений, главную, каталог,
карточку вещи, меню и фокус, темы, состояния загрузки/ошибки, календарь,
футер, карточки/формы владельца, выбор фото и диалоги. Матрица:
320/360/390/430/768/1024/1440 px, светлая и тёмная темы.

С настоящими Development Clerk-сессиями, локальным API/PostgreSQL и настроенным
Cloudinary проверены профиль, изоляция аккаунтов, создание/публикация объявления,
загрузка/перестановка/удаление фото, избранное, права чужого пользователя,
снятие с публикации и окончательное удаление. Двумя аккаунтами пройден сценарий
заявка → подтверждение → начало аренды → завершение, с сохранением старой цены
после редактирования и скрытия вещи. Дополнительно проверены все входы в кабинет
для гостя и настоящие формы входа/регистрации на телефоне и desktop в обеих темах.

Сценарии ошибок 409/503 и имени `Du` используют настоящую Clerk-сессию, но
подменённые ответы API: это детерминированные регрессионные проверки интерфейса,
а не утверждение о сбое настоящего сервера. Тест обновления кеша сначала посещает
пустой список аренд, затем создаёт заявку и возвращается в него через ссылки SPA.

Серверные проверки БД выполнялись в отдельном временном кластере, а не над данными
разработки. Реальные auth-тесты создают только временные аккаунты и свои объявления;
их записи и фото удаляются в teardown. `dev:all` также успешно запущен на Windows.

## Границы и оставшиеся проверки

- Это проверка локального проекта, не опубликованного HTTPS-сайта и не полный
  security/pentest или аудит сторонних зависимостей.
- Сборка предупреждает о JS chunk больше 500 kB; это предупреждение о размере,
  сборку оно не блокирует. DB-тесты также показывают предупреждение pg о будущей
  отмене параллельных запросов на одном клиенте; текущие проверки проходят.
- Реальные Android/iOS, VoiceOver/TalkBack, клавиатура, камера и установка PWA
  через HTTPS остаются в [списке device/deployment проверок](mobile-pwa.md).
- Ввод пароля/OTP, Google OAuth и фактическая регистрация через форму не автоматизировались:
  проверялась загрузка форм, а реальные сессии создавались тестовым API Clerk.
- Публичные Datenschutz/Impressum по-прежнему отмечены как незавершённые черновики;
  реквизиты владельца и юридические тексты требует подтвердить команда перед выпуском.

Ошибок сборки или сбоев в перечисленных успешно выполненных сценариях не осталось.
Это не гарантирует отсутствие ошибок за пределами проверенного покрытия.
