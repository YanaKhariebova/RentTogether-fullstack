# fix: handle booking failures and refresh rental lists

Входящие заявки скрывались при имени арендатора «Du», ошибки действий оставались
без сообщения, а сбой загрузки доступности открывал календарь без ограничений.
Исправлена обработка этих случаев, отклонённых Promise и ошибок избранного.
После создания заявки обновляется кеш аренд текущего пользователя.

Также исправлен ложный провал Prettier при Windows CRLF без массового форматирования
файлов команды. API, схема БД и бизнес-правила сохранены.

Проверены обе сборки/lint, форматирование, Prisma validate, TypeScript и diff;
20 тестов форм, 32 серверных, 44 DB/HTTP, 74 UI и 8 auth-сценариев.
Настоящий сценарий двумя аккаунтами включает фото/избранное и завершение аренды;
ошибки и устаревший кеш дополнительно проверяются детерминированно.
Подробности и границы: [site-audit.md](site-audit.md).

Ветка основана на `feat/mobile-pwa` (PR #37), чтобы review показывал только
исправления аудита. После включения PR #37 можно перенаправить этот PR в main.
Самостоятельно в main не объединять.
