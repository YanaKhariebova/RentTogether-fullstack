## Обязательная доводка до закрытия первой версии

1. Календарь: DateRangePicker использует включительный диапазон pickupDate–returnDate
   как disabled. Это расходится с серверной семантикой [pickup, return).
   Нужно согласовать доступность дня возврата и выбор возврата в день следующей
   выдачи, затем проверить UI и API вместе.
2. Кеш Booking: query keys my-rentals/incoming сейчас не включают userId при
   общем QueryClient со staleTime 30 секунд. Разделить данные аккаунтов и добавить
   проверку быстрого переключения; после мутаций обновлять связанные списки и
   доступность календаря. Полный сценарий не заменяет эту проверку.
3. Конкурентные cancel/approve: блокировка уже есть, но отдельного подтверждённого
   теста этой гонки пока нет. Добавить регрессионную проверку.
4. Ручной вход/регистрация: проверить обычный пароль/OTP и logout без signIn helper.
   Проверить ошибки сети, клавиатуру, mobile и обе темы на основных страницах.
5. Свести документацию с фактом: устаревшие чекбоксы TODO, общий ERD с Booking,
   wireframes, запуск с чистого окружения, демонстрационные данные и сценарий
   презентации 10–12 минут. Деплой по требованиям DCI необязателен.
6. Review команды, зелёный CI и merge согласованных PR в main; репетиция локальной
   демонстрации. После этого можно зафиксировать готовый MVP и открывать новые задачи.

## Порядок и оценка

Сначала корректность дат/кеша и тесты, затем финальный ручной прогон, затем
документация/демонстрация и review. Рабочий ориентир — 2–4 сосредоточенные сессии,
не гарантия срока: найденные дефекты и время командного review могут увеличить объём.
Откладывать работу до ноябрьских дат не требуется: по типу задач уже идёт интеграция.

Favorite не входит в исходный MVP. Яна может реализовать его отдельно после
готовности Booking; до его согласованного merge он не является условием завершения
первой версии. После добавления нужна повторная проверка удаления Item и каскада Favorite.
Старые локальные фото требуется отдельно разобрать, если команда решит делать deployment.
