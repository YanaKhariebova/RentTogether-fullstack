# Поиск населённого пункта и тёмные кнопки — 03.11.2026

## Поведение формы объявления

В Ort можно вводить название населённого пункта или немецкий почтовый индекс.
После 350 мс появляются варианты с регионом и индексами; доступен выбор мышью,
касанием и клавишами ArrowUp/ArrowDown/Enter, Escape закрывает список.
В Item.city сохраняется каноническое название, а не индекс.
Поиск пока ограничен Германией; другие страны требуют расширения адаптера.

Внешний провайдер: [OpenPLZ API](https://www.openplzapi.org/de/germany/).
Поиск по индексу 39104 возвращает Magdeburg; Koln предлагает Köln.
Open-Meteo проверен, но не выбран: для 39104 он вернул пустой ответ.
[FAQ провайдера](https://www.openplzapi.org/de/faq/) подтверждает бесплатное
использование и для коммерческих проектов. Источник указан рядом с подсказками.

## API и проверка сохранения

GET /api/locations?q=<строка> — публичный поиск, 2–100 символов.
Ответ: { places: [{ id, name, region, country, countryCode, postcodes }] }.
ID используется только для отображения вариантов и не записывается в Item.
Нужны именно населённые пункты, поэтому endpoint провайдера — /de/Localities.

Backend проверяет и нормализует город перед POST /api/items.
При PATCH проверяется только изменённое название; старые сохранённые значения
можно оставить без изменений, чтобы редактирование старых вещей не зависело
от доступности справочника. Неверный новый город: 422 CITY_NOT_FOUND.
Прямой ввод числа-индекса вместо города сохранить нельзя: нужно выбрать вариант.
Профиль и фильтр опубликованных городов этим пакетом не изменяются.
Старые записи в БД автоматически не переименовываются.

Неполный/пустой результат поиска и недоступный провайдер различаются.
При сбое справочника новые/изменённые города не принимаются вслепую:
503 LOCATION_SERVICE_UNAVAILABLE, пользователь может повторить запрос.
Запросы провайдеру идут с backend, тайм-аут 5 секунд.
Кеш ограничен 300 поисковыми запросами/10 минутами; одинаковые одновременные
запросы объединяются. Endpoint ограничен 60 запросами в минуту на req.ip.
За общим proxy Render несколько клиентов могут делить одну квоту, поскольку
приложение не доверяет произвольному X-Forwarded-For.

Параметры провайдера формируются сервером. Пользовательский текст не является
регулярным выражением; метасимволы POSIX BRE экранируются. Валидация сохранения
использует точное совпадение, подсказки — префикс. Строки одной местности с
разными PLZ объединяются в один вариант.

Новых npm-зависимостей, API-ключей, env и миграции для этой функции нет.
Нужно обновить backend и frontend вместе; старый API без /locations даст ошибку
подсказок. Общие маршруты и форматы существующего Item API сохранены.

## Тёмная тема

Для secondary Button и IconButton в dark используются theme-токены:
фон #1c2423, текст #79d3ab, граница #343d40. Primary/danger и светлая тема
сохраняют текущую палитру. Это убирает белую полосу Nachrichten в BookingList,
не меняя действия кнопки или компоненты сообщений Яны.
