## Изменения

- До 1024 px: компактный Header и боковая панель на нативном `dialog`.
  Основные маршруты, информационные страницы, вход/профиль, выход через Clerk
  и переключатель темы находятся в меню. Состояние загрузки аккаунта обозначено отдельно.
- Панель закрывается кнопкой, по фону, Escape, переходу по ссылке и при переходе
  к desktop. Есть aria-expanded/controls, начальный фокус, циклический Tab/Shift+Tab,
  возврат фокуса и блокировка прокрутки фона. Фон недоступен через нативный modal dialog.
- Внизу оставлены три быстрых раздела: Entdecken, Meine Anzeigen, Anfragen.
  Избранное и профиль доступны из меню. Общий нижний отступ и safe area резервируют
  место для панели, включая главную. При фокусе в поле ввода нижняя панель скрывается.
- На телефонах Hero показывает фото отдельной строкой над текстом. Кадр сохраняет
  оба лица, рукопожатие и коробку. Заголовок, описание и обе кнопки сохранены.
  Правила и исходный файл desktop Hero не заменены.
- Телефон получает через picture/srcset WebP 640 px (51 384 байта) или 960 px
  (82 692 байта) вместо исходного файла 278 880 байт. Экспорт из исходного фото
  и SVG воспроизводится командой `node scripts/mobile-assets.mjs` с установленным Edge
  или `PLAYWRIGHT_CHANNEL=chrome` с Chrome. Новые зависимости не добавлены.
- Исправлена ширина фильтров каталога на планшете, перенос пагинации, видимый
  фокус фильтров, размеры календаря и его кнопок (44×44). На 320 px календарь
  выходит на ширину экрана; семь дней помещаются без боковой прокрутки.
- Добавлены удобные вкладки заявок, перенос длинного содержимого карточек,
  safe area диалогов и футера, 16 px в полях на телефоне для предотвращения
  автоматического увеличения страницы iOS. У избранного появились повтор загрузки
  и сообщение об ошибке сохранения.

Inter, исходный SVG, зелёная/медовая палитра, светлая/тёмная темы и существующие
shared-компоненты сохранены. API, Prisma, защита маршрутов и правила бронирования
не изменены. Новые страницы и зависимости не создавались.

## PWA

Добавлены `public/manifest.webmanifest`, PNG 192/512, отдельная maskable 512
(знак внутри центральной безопасной области), Apple Touch Icon 180 и ссылки в HTML.
Manifest задаёт id/start_url/scope `/`, немецкий язык, название RentTogether,
`display: standalone`, зелёный theme_color и светлый background_color.

Service worker не регистрируется. Дополнительного кеша HTML, API, токенов или
персональных данных нет. Офлайн-работа, включая бронирование, не поддерживается:
нужен интернет. Обновления загружаются обычным образом при новом открытии/перезагрузке;
экрана, удерживаемого устаревшим service worker, нет.

Установка после deployment:

1. Android Chrome: открыть HTTPS-адрес → меню браузера → «Установить приложение»
   или «Добавить на главный экран» (название зависит от версии браузера).
2. iPhone/iPad Safari: открыть HTTPS-адрес → «Поделиться» → «На экран Домой»;
   включить «Открывать как веб-приложение», если этот переключатель показан.
3. Desktop Chrome/Edge: значок установки в адресной строке или установка
   сайта как приложения через меню браузера.

Автоматическое предложение установки зависит от браузера и его критериев;
собственный баннер установки не добавлен. Manifest не требует service worker
для этого сценария. Источники: [manifest, web.dev](https://web.dev/learn/pwa/web-app-manifest),
[Microsoft: installability](https://learn.microsoft.com/en-us/microsoft-edge/progressive-web-apps-chromium/webappmanifests),
[Apple: web app на iPhone](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/ios).

## Проверки и границы

- `npm.cmd run lint`, `npm.cmd run build`, `git diff --check`.
- UI Playwright в установленном Edge: 64 теста, включая матрицу
  **320, 360, 390, 430, 768, 1024, 1440 px**, обе темы, каталог/детали с API-fixtures,
  Header, Hero, календарь, футер и формы/карточки владельца.
- Проверены клавиатура, touch-emulation, размеры кнопок дат/навигации,
  отсутствие горизонтального переполнения страницы и календаря, все способы
  закрытия меню, удержание/возврат фокуса и закрытие при resize.
- Проверены фактический выбор мобильного изображения без запроса desktop-файла,
  размеры PNG, доступность manifest и отсутствие регистрации service worker.
- Отдельный auth-тест использует временные Development Clerk-аккаунты и настоящие
  локальные API/PostgreSQL: профиль, пустое избранное, оба пустых списка заявок
  во всей матрице размеров и тем. Заполненные карточки каталога/владельца проверяются
  отдельно с fixtures. Полный реальный rental flow этим мобильным тестом не повторяется.
- Визуально просмотрены снимки главной на 390/1024/1440 и меню на 390 px.
  Сборка выдаёт прежнее предупреждение Vite о JS chunk больше 500 kB.

Первый auth-прогон обнаружил остановленную локальную БД. Для проверки запущена
существующая PostgreSQL и применена уже находившаяся в main миграция `favorites`;
env-файлы и миграции в этом PR не редактировались.

На настоящих Android/iOS остаются: экранная клавиатура и автозаполнение,
safe area в portrait/landscape, VoiceOver/TalkBack, выбор/съёмка/перестановка фото,
низкий экран, системный Back, установка/иконки/запуск standalone, вход и выход
в установленном приложении. Эмуляция viewport и touch не заменяет эти проверки.

После deployment проверить HTTPS без mixed content, получение manifest/иконок
без редиректа на HTML, загрузку `/` и SPA deep links, Clerk на production origin,
установку в Android/iOS/desktop и обновление установленного приложения.
Новые переменные окружения, серверные маршруты и изменения хостинга не нужны,
если существующий deployment уже раздаёт Vite `dist`, поддерживает SPA fallback
и HTTPS. В `dist` должны попасть `manifest.webmanifest`, `icons/` и `media/`.
