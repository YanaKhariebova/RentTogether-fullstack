# Контракт API объявлений

Контракт согласован Ольгой и Яной 27 октября 2026 года. Ольга отвечает за
данные объявлений и кабинет владельца, Яна реализует публичные GET endpoints.
Публичные GET реализованы Яной и объединены с owner API из main 29.10.2026.
Перевод страниц каталога на API остаётся отдельным изменением Яны.
Owner API ниже реализован Ольгой 28 октября 2026 года. Его HTTP-поведение
проверено на PostgreSQL с тестовой подтверждённой идентичностью.

## Объект объявления

```json
{
  "id": "item-1",
  "title": "Beamer für einen Filmabend",
  "description": "Ein Beamer mit HDMI-Anschluss.",
  "pricePerDay": "15.50",
  "city": "Berlin",
  "category": { "id": "category-1", "name": "Elektronik" },
  "images": [{ "id": "image-1", "url": "https://storage.example/beamer.webp", "order": 0 }],
  "owner": { "id": "user-1", "name": "Olga", "city": "Berlin" },
  "isPublished": true
}
```

Все ID в JSON — строки. Цена — строка EUR с двумя знаками после точки.
На форме `15,50` проверяется и переводится в 1550 центов, затем адаптер
формирует API-значение `"15.50"`. Клиент не передаёт владельца при создании:
его определяет сервер по авторизации.

Изображения приходят отсортированными по `order`, начиная с нуля.
Первое изображение — обложка. Email, телефон и Clerk ID не выдаём публично.

В Prisma Item есть `createdAt` для сортировки; в публичном ответе дата
пока необязательна. Локальный DTO кабинета содержит `createdAt` и `updatedAt`
как ISO-строки. Endpoint занятых дат Яна согласует отдельно.

## GET api items

Путь: `GET /api/items`. Только опубликованные объявления.

| Query                  | Правило                                             |
| ---------------------- | --------------------------------------------------- |
| `q`                    | Поиск по названию и описанию без учёта регистра     |
| `city`                 | Точное совпадение города без учёта регистра         |
| `categoryId`           | ID категории                                        |
| `minPrice`, `maxPrice` | Границы включены, значения в евро, например `10.50` |
| `page`                 | Целое число от 1; по умолчанию 1                    |
| `limit`                | Целое число 1–50; по умолчанию 12                   |

Сортировка: сначала новые. Дополнительный порядок по ID для одинакового
`createdAt` предложен в черновике, точное направление согласуем при реализации.

```json
{
  "items": [],
  "pagination": { "page": 1, "limit": 12, "total": 0, "totalPages": 0 }
}
```

Элементы `items` имеют структуру объекта выше. Пустой результат — HTTP 200,
неверные query — HTTP 400 с `VALIDATION_ERROR`.

## GET api items id

Путь: `GET /api/items/:id`. Ответ — `{ "item": ... }`, где `item` имеет
структуру объекта выше. Отсутствующее или неопубликованное объявление —
HTTP 404 с `ITEM_NOT_FOUND`.

## Ошибки

```json
{
  "error": {
    "code": "ITEM_NOT_FOUND",
    "message": "Die Anzeige wurde nicht gefunden.",
    "fields": {}
  }
}
```

В проверенном foundation PR Влада № 3 формат `fields` определён как
`Record<string, string[]>`; общие ошибки формы используют ключ `_form`.
Форма Ольги может показывать первое сообщение каждого поля.

## Owner API

Все следующие маршруты требуют Clerk JWT. Middleware определяет локального
пользователя через `res.locals.currentUser`; ownerId из тела не принимается.
На frontend useApi уже добавляет `/api` и Bearer token.

### POST api items

`POST /api/items`, HTTP 201, ответ `{ "item": OwnerItem }`.

```json
{
  "title": "Beamer für einen Filmabend",
  "description": "Ein Beamer mit HDMI-Anschluss.",
  "city": "Berlin",
  "categoryId": "10000000-0000-4000-8000-000000000001",
  "pricePerDay": "15.50"
}
```

Используется существующий UUID категории из GET /api/categories. Название —
3–100 символов, описание — 10–5000, город — 2–100; строки обрезаются по краям.
Цена — положительная строка с точкой и двумя знаками, максимум `999999.99` EUR.
Числовой JSON `15.5` и строка `"15,50"` не являются API-форматом цены.

Объявление создаётся черновиком: `isPublished: false`, `images: []`.
Поля id, ownerId, images и isPublished в этом запросе запрещены.
Форма готового объявления требует фото, но серверный черновик нужен для
последующей загрузки фотографий по ID вещи.

### PATCH api items id

`PATCH /api/items/:id`, HTTP 200, ответ `{ "item": OwnerItem }`.
Принимается непустой частичный объект полей POST, а также `isPublished`.
ID должен быть UUID. Владельца и фотографии этим запросом изменить нельзя.

```json
{ "pricePerDay": "20.00", "isPublished": true }
```

Публикация без сохранённого фото — HTTP 409, `ITEM_IMAGES_REQUIRED`, сообщение
поля `images`. Перед записью сервис блокирует строку Item через FOR UPDATE,
проверяет владельца и наличие изображений в транзакции. Будущие мутации
фотографий должны использовать ту же блокировку.

### DELETE api items id

`DELETE /api/items/:id`, HTTP 200, ответ `{ "item": OwnerItem }`.
Снимает объявление с публикации, устанавливая `isPublished: false`.
Запись, изображения и будущие бронирования не удаляются. Повторный запрос
владельца допустим и снова возвращает скрытое объявление.

### GET api my items

`GET /api/my/items`, HTTP 200:

```json
{ "items": [] }
```

Возвращает только объявления текущего локального пользователя, включая
черновики и снятые с публикации. Сортировка: createdAt DESC, id DESC.
Пагинация для кабинета пока не предусмотрена.

### OwnerItem и ошибки

OwnerItem содержит поля публичного Item выше и дополнительные ISO-строки
createdAt/updatedAt. Цена всегда форматируется сервером в строку с двумя
знаками. Фотографии отсортированы, storageKey не выдаётся, owner содержит
только id/name/city. Frontend-типы OwnerItemResponse/OwnerItemsResponse находятся
в `src/features/items/types/item.ts`.

| Ситуация                                        | HTTP и code               |
| ----------------------------------------------- | ------------------------- |
| Нет сессии                                      | 401 UNAUTHENTICATED       |
| Изменение чужого объявления                     | 403 FORBIDDEN             |
| Нет объявления                                  | 404 ITEM_NOT_FOUND        |
| Неверные поля/UUID                              | 400 VALIDATION_ERROR      |
| Категория не существует                         | 400 CATEGORY_NOT_FOUND    |
| Публикация без фото                             | 409 ITEM_IMAGES_REQUIRED  |
| Связанные данные удалены одновременно с записью | 409 ITEM_RELATION_CHANGED |

Формат ошибок общий: error.code/message/fields, значения fields — массивы строк.
Серверные загрузка, удаление и перестановка реализованы 29 октября 2026.
Для разработки подключён локальный адаптер; облачный провайдер ещё не выбран.
Контракт фотографий ниже и в [памятке хранилища](image-storage.md).
Frontend кабинета подключён к реальному API через TanStack Query (29.10.2026).

## PATCH api items id images order

Реализовано 29.10.2026. `PATCH /api/items/:id/images/order`, Clerk JWT обязателен.

```json
{
  "imageIds": ["40000000-0000-4000-8000-000000000002", "40000000-0000-4000-8000-000000000001"]
}
```

Передаётся полный список UUID всех текущих фото объявления в желаемом порядке,
от 1 до 8, без повторов и дополнительных полей. Первый ID становится обложкой.
HTTP 200: `{ "item": OwnerItem }`, фотографии упорядочены от нуля.

Сервис блокирует Item той же блокировкой `FOR UPDATE`, что и публикация,
проверяет владельца и точное совпадение набора ID с БД. В транзакции сначала
назначаются временные свободные позиции, затем окончательные: это позволяет
поменять местами 0 и 1 без нарушения уникальности `(itemId, order)`.
Обновляется Item.updatedAt; URL, storageKey, createdAt и статус публикации сохраняются.

- Без входа — 401 `UNAUTHENTICATED`.
- Чужой владелец — 403 `FORBIDDEN`.
- Нет объявления — 404 `ITEM_NOT_FOUND`.
- Неверные UUID, повторы, пустой/слишком большой список — 400 `VALIDATION_ERROR`.
- Пропущенные, чужие или уже удалённые ID — 409 `ITEM_IMAGES_CHANGED`. Нужно
  заново загрузить объявление; частичные изменения не сохраняются.

Маршрут проверен HTTP-тестами с PostgreSQL, включая конкурентные запросы.
Frontend вызывает совместимый PUT для сохранения порядка фото. PATCH доступен другим клиентам и возвращает OwnerItem.

## Загрузка и удаление фото — 29.10.2026

`POST /api/items/:id/images`: требуется Clerk JWT и UUID объявления владельца.
Тело — **один бинарный файл**, Content-Type `image/jpeg`, `image/png` или
`image/webp`. Не JSON, не multipart: формат совместим с текущим прототипом Яны.
Ограничения: 5 МБ, до 8 фотографий на item, до 25 мегапикселей, без анимации.
Сервер проверяет декодируемое содержимое, MIME и удаляет EXIF/GPS при пересохранении.

HTTP 201:

```json
{
  "image": {
    "id": "40000000-0000-4000-8000-000000000001",
    "url": "http://localhost:3000/uploads/40000000-0000-4000-8000-000000000002.png",
    "order": 0
  }
}
```

`storageKey` не выдаётся; номер добавляется в конец. Превышение лимита количества —
409 `ITEM_IMAGES_LIMIT`; неверное/повреждённое содержимое — 400 `INVALID_IMAGE`.
Слишком большой HTTP body — 413 `PAYLOAD_TOO_LARGE`; размер после нормализации —
413 `IMAGE_TOO_LARGE`. Не настроенный storage — 503 `IMAGE_STORAGE_NOT_CONFIGURED`.
Права и существование item проверяются перед обработкой бинарного тела и ещё раз
под блокировкой при записи в БД. Файл удаляется при откате регистрации в БД.

`DELETE /api/items/:id/images/:imageId`: владелец удаляет фото, HTTP 204 без тела.
Чужое объявление — 403; нет фото у данного item — 404 `IMAGE_NOT_FOUND`.
Последнее фото опубликованного объявления удалить нельзя: 409 `ITEM_IMAGES_REQUIRED`.
Сначала нужно снять объявление с публикации. После удаления позиции оставшихся
фото уплотняются от нуля. Удаление объекта из хранилища имеет долговечное задание
ImageCleanup и повторяется при временном отказе провайдера.

`PUT /api/items/:id/images/order` поддерживается для совместимости с прототипом
Яны: та же валидация и сервис, что у PATCH выше, но ответ HTTP 204 без тела.
Новые клиенты могут использовать PATCH и получать обновлённый OwnerItem.

## Подключение кабинета — 29.10.2026

Кабинет использует GET /my/items и реальные категории, сохранение/фото/публикацию.
Новые объявления сохраняются черновиками; кнопка «Veröffentlichen» в Meine Anzeigen
публикует вещь только после загрузки фото. Снятие с публикации требует подтверждения.
Query key кабинета содержит Clerk userId; provider формы перемонтируется при смене
аккаунта. После успешных и частично неуспешных мутаций обновляются my-items и items,
чтобы кабинет, будущие query каталога и detail увидели актуальные данные.

Save-сессия формы сохраняет известный ID черновика и ID успешно загруженных фото.
Повтор после известного частичного сбоя продолжает работу с ними. При замене фото
опубликованная вещь временно снимается с публикации; исходный статус возвращается
после сохранения полного набора и порядка. При ошибке остаётся черновик; форма
показывает сообщение и позволяет исправить ввод/повторить сохранение.

Мутации не повторяются автоматически. Потеря ответа после фактической записи
на сервере остаётся неоднозначной: полной идемпотентности для POST пока нет.
В такой ситуации нужно проверить Meine Anzeigen перед повторным созданием.

## Список городов каталога — дополнение 29.10.2026

`GET /api/items/cities`, публичный ответ HTTP 200:

```json
{ "cities": ["Berlin", "Magdeburg"] }
```

Возвращает различные города только опубликованных вещей, по алфавиту, независимо
от пагинации и текущего фильтра. Нужен для стабильных вариантов dropdown/radio.
Маршрут объявлен перед /:id, чтобы слово cities не проверялось как UUID.
Query key: `['items', 'cities']`; существующая invalidation items обновляет его
после публикации, скрытия или изменения города. Старые GET /items и /items/:id
сохраняют формат. Фильтр city остаётся одним значением.
