# Согласованный публичный контракт объявлений

Контракт согласован Ольгой и Яной 27 октября 2026 года. Ольга отвечает за
данные объявлений и кабинет владельца, Яна реализует публичные GET endpoints.
Наличие контракта не означает, что серверные маршруты уже реализованы.

## Объект объявления

```json
{
  "id": "item-1",
  "title": "Beamer für einen Filmabend",
  "description": "Ein Beamer mit HDMI-Anschluss.",
  "pricePerDay": "15.50",
  "city": "Berlin",
  "category": { "id": "category-1", "name": "Elektronik" },
  "images": [
    { "id": "image-1", "url": "https://storage.example/beamer.webp", "order": 0 }
  ],
  "owner": { "id": "user-1", "name": "Olga", "city": "Berlin" },
  "isPublished": true
}
```

Все ID в JSON — строки. Цена — строка EUR с двумя знаками после точки.
На форме `15,50` проверяется и переводится в 1550 центов, затем адаптер
формирует API-значение `"15.50"`. Клиент не передаёт владельца при создании:
его определяет сервер по авторизации.

Изображения приходят отсортированными по `order`, начиная с нуля.
Первое изображение — обложка. Email, телефон и Clerk ID не выдаём публично.

В Prisma Item требуется `createdAt` для сортировки; в публичном ответе дата
пока необязательна. Локальный DTO кабинета содержит `createdAt` и `updatedAt`
как ISO-строки. Endpoint занятых дат Яна согласует отдельно.

## GET api items

Путь: `GET /api/items`. Только опубликованные объявления.

| Query | Правило |
| --- | --- |
| `q` | Поиск по названию и описанию без учёта регистра |
| `city` | Точное совпадение города без учёта регистра |
| `categoryId` | ID категории |
| `minPrice`, `maxPrice` | Границы включены, значения в евро, например `10.50` |
| `page` | Целое число от 1; по умолчанию 1 |
| `limit` | Целое число 1–50; по умолчанию 12 |

Сортировка: сначала новые. Дополнительный порядок по ID для одинакового
`createdAt` предложен в черновике, точное направление согласуем при реализации.

```json
{
  "items": [],
  "pagination": { "page": 1, "limit": 12, "total": 0, "totalPages": 0 }
}
```

Элементы `items` имеют структуру объекта выше. Пустой результат — HTTP 200,
неверные query — HTTP 400 с `VALIDATION_ERROR`.

## GET api items id

Путь: `GET /api/items/:id`. Ответ — `{ "item": ... }`, где `item` имеет
структуру объекта выше. Отсутствующее или неопубликованное объявление —
HTTP 404 с `ITEM_NOT_FOUND`.

## Ошибки

```json
{
  "error": {
    "code": "ITEM_NOT_FOUND",
    "message": "Die Anzeige wurde nicht gefunden.",
    "fields": {}
  }
}
```

Общий формат `fields` и контракты изменяющих маршрутов нужно подтвердить
с Владом до подключения frontend к Express API.
