## Проверки и команды

```sh
npm run test:items
npm --prefix server test
npm --prefix server run db:check
PLAYWRIGHT_CHANNEL=chrome npm run test:ui
PLAYWRIGHT_CHANNEL=chrome npm run test:auth -- tests/auth/items.spec.ts --grep real.owner.creates
npm run build
npm --prefix server run build
npm run lint
npm --prefix server run lint
npm run format:check
```

PLAYWRIGHT_CHANNEL=chrome нужен только при использовании установленного Chrome.
Для другой среды используйте доступный канал согласно auth-verification.md.
UI-стенд tests/fixtures/owner-items.html изолирован и не подменяет авторизацию
приложения. В нём проверяются состояния и клавиатура; безопасность и хранение —
серверными/DB-тестами и настоящим Clerk browser test. Для переключения тем и
формы проверены 360, 390, 768, 1024 и 1440 px. Ручной пароль/OTP не покрываются
официальным signIn helper и относятся к общей финальной проверке авторизации.

## Короткая демонстрация части Ольги

1. Войти владельцем и открыть Meine Anzeigen.
2. Создать объявление «Demo Beamer», Berlin, Elektronik, 15,50 EUR/Tag.
3. Добавить два разрешённых к использованию фото, показать порядок и preview.
4. Сохранить черновик, обновить страницу и опубликовать.
5. Показать вещь в каталоге, отредактировать цену или обложку, обновить страницу.
6. Снять с публикации через подтверждение: вещь остаётся в кабинете.
7. На отдельном объявлении без заявок показать Löschen и сначала Abbrechen.
8. Пояснить: объявления с заявками защищены от удаления, история сохраняется.

Презентационные данные создаются через обычную форму от выбранного владельца;
seed не публикует случайные вещи и не добавляет фото автоматически. Случайных
реальных пользователей/объявления при демонстрации не изменять.

## Что передать команде на review

- Последний вариант главной, включая desktop/mobile и обе темы.
- Реальные операции владельца и обработка ошибок сохранения/удаления.

## Что не является недоделкой этой зоны

Календарь, кеш списков Booking, cancel/approve и Favorite относятся к Яне;
ручной вход/регистрация и общие auth-настройки — к Владу/командной проверке.
Для локального MVP дополнительных изменений хранилища не требуется. Перенос
старых фото из server/uploads/ нужен отдельно, только если команда выберет deployment.
